### Rules and co-op sync (the code M4b changes next)
- **Co-op trusts the client.** The server trusts the suit level, the rover distance and the moment of a collapse that a player's game reports, and checks what it can: find ids, the distance from the last position, capacity, the phase and the driver's seat. Spec §5 has positions carry the suit level and the load, and M1–M3 already trust client positions. The cost: a modified client could keep a full suit, skip hold times or teleport in co-op, which is low stakes for a classroom LAN game. Revisit it if cheating ever matters.
- `driving()` accepts an undefined crew id (`src/expedition.js:67`): `park(m, undefined, pos)` moves a parked rover and `setRoverDriven(m, undefined, 399)` drains it. `park` also ignores `m.status` (`:233`), so a stray park after the mission ends moves the rover. Fix: `!!id &&` in `driving()` and a status check in `park`.
- `setSuit` (`src/expedition.js:254`) turns `''`, `false`, `[]` and `null` into 0, which empties the suit instead of ignoring junk, and the server's guard `body.suit != null` (`lib/rooms.js:98`) lets them through (`driven` at `:99` too, harmlessly: it only rises and is capped). One `typeof === 'number'` check in `setSuit` fixes both.
- `inBaseZone` is closed at +192 (`src/expedition.js:62-63`) while the plan's constraint says −128..191 (x = 192 is tile 3); the zone-edge check stops at x = 191.8. Shelters reuse the zone, so settle which is right then.
- `expeditionAction`'s `default:` runs `park` (`lib/rooms.js:42`): an action added to `EXPEDITION_ACTIONS` (`:24`) without a case silently parks. Make `park` explicit and `default` return `{ error: 'badAction' }`, before M4b adds its first new action.
- A heartbeat in flight during a revive can set the server's suit to 0 again (the client adopts `X.suitOf` on the down → up change at `src/surface-eva.js:158`, and its next send restores 30 within about 110 ms plus latency). Harden it by not sending the suit while down.
- `park` is sent once, fire and forget (`src/surface.js:768`; `src/surface-eva.js:32` says quiet actions are "retried or harmless"): a transport failure leaves `x.rover = { driver }` on the server (`position()` never clears it), so teammates get `taken` until the round advances or the driver boards or parks again.
- **The canister button can waste a canister.** `X.useCanister` (`src/expedition.js:145`) accepts any suit level, even in the base zone, and caps the suit at 150 s. The layer still says "+45 s of suit oxygen." (`src/surface-eva.js:130-137`), and it shows the button whenever a canister is carried (`src/surface-eva.js:110`). A player who presses it early to see what it does loses the 30 kg of O₂ the canister would bank. Fix: hide the button, and refuse the action, above 105 s or in the base zone. In co-op the canister button stays visible while you are down (`src/surface-eva.js:100`, `src/surface-eva.js:110`); pressing it or Q is refused with "You have collapsed." The same guard should hide it. M4b's O₂ ruptures change canisters anyway.
- **A reload is a free trip home.** Solo saves keep no position, and a co-op seat's last server position isn't restored, so a reloaded avatar starts by the HQ (`ensurePlayer`, `src/surface.js:136`). The base zone then delivers the backpack (`src/surface-eva.js:206`). It favours the player: the walk home costs nothing, and co-op teammates see a teleport. The fix wave handles only a collapsed seat, which lies where it fell (`src/surface.js:364`). M4b: save the solo position, and restore a co-op seat from `room.positions` on a fresh look.
- **The parked rover is drawn over the fallen driver.** After a co-op collapse while driving, the rules park the rover on the collapse spot, and the rover sprite sorts at `r.y + 10` (`src/surface-eva.js:327`), after the avatar, so the rover is drawn over the fallen driver. The red name tag, the cross and the revive prompt stay visible. Fix with the co-op collapse and rover drawing work (an offset, or draw a fallen astronaut above a parked rover).
- **A collapsed co-op player facing the rover bay is still offered "E Drive the rover":** `focusAt` still returns the `rover` focus (`src/surface.js:674`), the prompt shows it (`src/surface.js:735`), and E is now ignored without a word (the guard at `src/surface.js:772`). Before the fix wave the refusal said "You have collapsed." (`eva.err.collapsed`). The HUD's collapse note still shows. Fix: don't offer the bay as a rover focus while down, or say `eva.err.collapsed` in the guard.
- Tests for the rules and rooms: the `canister` and `pickup` actions are never sent through `act()` and `load` is only asserted as 0 (`test/rooms.test.js:467`); no test shows that a refused action doesn't broadcast; the suit test waits 150 ms against the 80 ms throttle (the file's existing pattern).
- Tests for the exploring layer, paths no test reaches: the keep-going re-hold (`src/surface-eva.js:235`) and the revive and pickup hold paths (only the find hold is covered); the `id !== me` half of the fresh-look trigger (`src/surface-eva.js:146`), which a takeover sync would pin (controlId `diego`, `suits.diego = 40` → suit 40); the driven reset on a new look (`src/surface-eva.js:152`), whose deletion survives every test (pin it: `roverDriven = 100` → `resolveTurn` → `sync(next)` → `report().driven === 0`). `src/surface-eva.js:155` is equivalent to `false`, because `src/surface-eva.js:159` re-syncs it.

### From the Task 8 QA

## For the M4c plan (points of interest)
- **Keep find ids stable.** A find's id is its index in its chunk's array (`"<cx>,<cy>:<n>"`), and every saved mission's `sites` (loads left) is keyed by it. Spec §2.3 lets landmarks and structures override terrain: if M4c filters finds out of a landmark's footprint by rebuilding the array, the indices shift and saved `sites` point at different finds. Keep `placeFinds`' output untouched and hide finds by footprint when they are read, or migrate `sites`.
- Landmarks, discovery cards and lava-tube interiors.
- Kestrel structures: hab pods add a once-a-round refill through `expedition.refills`, which the round roll-over already resets.
- Formations, with sourced facts.

### Worldgen and the shared world cache
- `findById` builds the chunk an unvalidated id names before the position check (`src/expedition.js:47`): 1,000 far ids cost about 200 ms and evict other rooms' chunks from the shared 256-chunk cache (`:27`). Fix: in `collect`, refuse an id whose chunk isn't the one containing `pos`. M4c adds more checked actions on the same cache, so do this first.
- `findsIn` returns the cache's own unfrozen arrays (`src/expedition.js:38`): a consumer that annotates a find corrupts every mission with that seed. Freeze in `chunkAt` or document it as read-only; structures and landmarks will read the same chunks.
- The ice-spot loop doesn't apply `FIND_GAP` (`src/worldgen.js:347-352`); the 5-tile gap holds there only because features are spaced. Add the `out.some` filter or a comment.
- The region nibble decode is repeated (`src/worldgen.js:351`, `:360`, `regionOf` at `:405`), and the salts 500, 540 and 580 overlap if `FIND_DARTS` grows past 40.
- No direct test that canyon middles hold ice (117 of 117 are right today); mirror the crater assertion in `test/worldgen-finds.test.js`.
- About 24 % of craters (474 of 1,983 measured) have no ice find on their floor, because ice goes only in crater centres and canyon middles that a chunk owns (3 tiles inside). Spec §2.4 only says "crater floors, canyons, Icy Plains", which holds. Clamping would move the pinned finds hash (`0e84f5a1`) and the balance tuned on it.
- `marks` peeks at about 100 chunks per rebuild and is cached for 150 ms, so it ignores position changes inside that window (`src/surface-eva.js:341-343`). Landmarks and structures will join the markers, so make it incremental then.
